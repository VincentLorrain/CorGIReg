# Operation graph JSON

This is the portable **input IR**, selected by `--format json`. It describes
operations and directed producer-to-consumer edges. It is separate from the
[pattern language](pattern-language.md) and [match report](match-report-json.md).

The executable example is [examples/graph.json](examples/graph.json):

```json
{
  "nodes": [
    {"id": 42, "op": "A", "name": "first_A"},
    {"id": 0, "op": "A", "name": "second_A"},
    {"id": 9, "op": "B", "name": "last_B"}
  ],
  "edges": [[42, 0], [0, 9]]
}
```

From the repository root, after installing the CLI:

```sh
corgireg -i doc/examples/graph.json -r 'A+->B' -o matches.json
```

## Fields and normalization

| Field | Contract |
| --- | --- |
| `nodes` | Required array of node objects; may be empty. |
| `nodes[].id` | Required unique integer in `[0, 18446744073709551615]`. Zero is valid; booleans and fractional numbers are invalid. |
| `nodes[].op` | Required nonempty string identifying the original operation type. |
| `nodes[].name` | Optional string, defaults to the decimal ID. Names need not be unique. |
| `nodes[].predicate` | Generated by normalization; an input value is overwritten. |
| Other node fields | Preserved as metadata and available to node-library rules. |
| `edges` | Required array of two-element arrays `[producer_id, consumer_id]`. Both IDs must exist. |

Nodes are sorted by ID; edges are deduplicated and sorted. Array order is not
execution order. The graph has no required `schema_version` field; unknown
top-level properties are discarded. Do not use top-level properties for metadata
that must survive import. Consumers using floating-point JSON numbers, such as
JavaScript, must preserve large IDs without rounding.

Each character outside ASCII letters, digits and underscore in `op` becomes `_`
in the raw predicate: `stablehlo.convolution` becomes `stablehlo_convolution`.
Two different operation names normalizing to the same predicate are rejected.
A [node library](node-library.md) can expose a semantic predicate such as `conv`.
Its `op_types` still refers to original `op` strings.

Edges express adjacency. An optional `connections` array preserves operand
bindings without changing that adjacency:

```json
{
  "nodes": [{"id": 0, "op": "X"}, {"id": 9, "op": "Sub"}],
  "edges": [[0, 9]],
  "connections": [
    {"from": 0, "to": 9, "input": 1, "output": 1},
    {"from": 0, "to": 9, "input": 2, "output": 1}
  ]
}
```

`from` and `to` must reference a pair present in `edges`. `input` identifies
the destination input; `output` identifies the source output. Ports are optional
positive 32-bit integers (1..4294967295); omitted or null means unspecified.
Connections are sorted and exact duplicates removed. Distinct ports between
the same nodes remain distinct. An edge without connection records is unnumbered.
For an edge with records, those records are authoritative; no extra unnumbered
connection is implied. To include one, supply a record with both ports null.

`X-2->Sub` requires input 2; `X->Sub` and `X-*->Sub` ignore port numbers.
The reverse spelling is `Sub<-2-X`. Output ports are preserved but have no
pattern selector in this version. Port labels do not change node-degree or
strict-node coverage semantics. An `inputs` array is metadata; it does
not create edges. Self-loops and cycles are not rejected by JSON normalization;
matching still obeys the runtime's [termination rules](match-traces.md).

ONNX and StableHLO readers preserve operation-to-operation input/output positions
in `connections`, converting zero-based IR positions to one-based ports. Repeated
operands and gaps from absent optional arguments retain their original positions.
Function inputs and initializers remain node metadata rather than synthetic
operation nodes; this representation is not yet a complete executable IR.

## Metadata and arguments

```json
{
  "id": 12,
  "op": "Conv",
  "name": "encoder/conv_0",
  "inputs": ["image", "weights", ""],
  "attributes": {"kernel_shape": [3, 3], "group": 1}
}
```

This is a node object, to place in `nodes`. `attributes` and `inputs` are
conventions understood by the supplied definitions, not mandatory graph fields.
Rules can address any preserved node property. Empty input strings represent
omitted optional slots during rule evaluation; null is present. Input indices
remain unchanged. See [NodeTest rules](node-rules.md) for presence, types, key
regexes and comparisons. Transported metadata supports finite numbers, strings,
booleans, null, arrays and objects, with 64-level nesting and one million items
per collection. Integers must fit signed or unsigned 64-bit storage.

## Other source IRs

ONNX and StableHLO importers produce this normalized operation graph. IDs refer
to imported operations, not tensor indices. Their supported subsets, naming,
metadata and rejected constructs are documented in [importers](importers.md).
For a custom in-memory IR, use a [GraphView adapter](graph-adapters.md).
